# Watch discovery source qualification: documentation pass

Investigated 2026-10-27 for [Which source routes can support an honest watch discovery claim?](tickets/source-qualification.md). This is an evidence asset, not the ticket's accepted resolution. **No route is qualified by this pass.** Public official documentation was read; no merchant listing, connector, account, basket or checkout was exercised. Source inspection and retained watch research are distinct from fresh observations of offers.

## Recommendation and evidence boundary

Start with the four contrasting cases already proposed in [the corpus review](watch-research-context.md): Militado ML05/ML05B (movement ambiguity), Addiesdive AD2066 mint (colour conflict), San Martin SN0144 (size/SKU/accessory conflict), and Merkur Lightning salmon (unresolved reference and missing offer). Add a **Casio MTP-B145D exact colour reference** as the smallest extra case for mainstream UK/international and used-market coverage. The exact suffix remains to be selected from manufacturer evidence; an unspecified family is a search query, not an exact configuration. Do not replace a zero-result route with an unrelated watch to claim success.

This five-case cohort deliberately does not claim market representativeness. It exercises new/used separation, manufacturer/store identity, variant selection and abstention. WD1863 revisions and the Sugess coupon case stay in the retained corpus for later tickets. No prices or claimed discounts from that corpus are adopted here.

Evidence levels: **S** = inspected repository source; **H** = retained historical corpus/audit; **D** = current public first-party documentation; **L** = newly observed live offer. There are zero L observations. Status describes this plan: **provisional** = plausible route awaiting qualification; **blocked** = access/terms prerequisite unresolved; **unsupported** = not a suitable available route for the stated use. “Qualified” requires later receipts, not a registration, fixture or official API description.

## Collection and retention findings

The Shopify adapter's `/products.json?limit=250` is an implementation assumption, not a cross-store completeness contract. It neither pages nor filters that returned inventory by the preceding search query, and currency can default to GBP. Current official Shopify Storefront documentation describes a storefront API, not permission to collect every merchant's public JSON endpoint. Per-store consent, currency context, variant URL and pagination remain qualification gates. [Source](../../../src/pricerecon/connectors/shopify.py), [Shopify reference](https://shopify.dev/docs/api/storefront/latest).

Do not begin a longitudinal archive by assuming all acquired content can be kept. eBay's licence permits limited necessary intermediate copies with deletion when no longer needed; restrictions include certain derived information and AI training uses. The reviewed text does **not** settle the intended historical-price archive's permissibility. Record that as an unresolved access/use prerequisite before acquisition, rather than inventing a universal 24-hour or 30-day rule. [API licence](https://developer.ebay.com/join/api-license-agreement). Brave storage entitlement must be checked against the actual plan. Reddit's approved use/deletion obligations cannot be met merely by labelling data public. All other routes' retention permission remains unknown unless their specific terms are checked. Public documentation licensing is not a licence to archive merchant content or images.

No reviewed route supplies a demonstrated end-to-end freshness SLA for selected UK offers. Record retrieval time and any source update time separately; a fresh search fetch can contain stale indexed information. Proposed repeat measurements below are an experiment, not an accepted production cadence.

## Proposed bounded live read-only protocol — original proposal

Update: the user subsequently approved this first pass; [execution receipts](source-qualification-live-pass.md) record its preflight stops and limits. The numbered text below preserves the reviewed proposal. Approval does not extend to repeat sessions or broader access.

This protocol can produce access/field receipts, **not** complete delivered-price or coupon verification. It requests no accounts, secret lookup, connector execution, background jobs or application changes.

1. **Preflight:** obtain explicit approval for the named public hosts and budget below. Read applicable terms/robots for the selected route; an explicit disallow or unresolved permission for automated collection makes that route blocked. User approval cannot override source conditions. Check manufacturer/store identity where needed. No disguised user agent, proxy rotation, CAPTCHA solving or bypass.
2. **Hosts:** `www.aliexpress.com`, `www.ebay.co.uk`, `www.chrono24.co.uk`, `www.militadowatch.com`, `www.watchshop.com`, `www.watchgecko.com`, `www.sakurawatches.com`, `www.sanmartin.watch`, `shopping.google.com`, `search.brave.com`, `www.hotukdeals.com`, `www.reddit.com`. Documentation/help on each same host is allowed. Cross-domain merchant redirects are recorded but not followed unless the destination is already listed. API hosts are excluded: credentialed API routes require a separate explicit authority and entitlement check.
3. **Queries:** the five cohort names above, exact-reference terms where known, plus one broad query `watch` only on a merchant's watch category if necessary. For community routes use `Militado`, `Addiesdive`, `San Martin`, `Merkur` and `Casio MTP-B145D`; do not demand returned matches. For search/aggregator leads retain both original and final merchant URLs.
4. **Caps:** one 60-minute session; at most **60 top-level document navigations**, including preflight terms/robots, search pages, details and redirects; at most two result/category pages per host, 20 inspected result cards per host and two offer detail pages per host. One navigation at a time with at least five seconds between top-level requests to a host. Browser subresources are not individually capped by this navigation count; record that limitation. No bulk image or catalogue download. Stop at the first global cap even with families untested.
5. **Allowed interactions:** ordinary public navigation, search, sorting, selecting an already displayed variant and choosing UK in a public country selector if no account/address is required. Read visible stock, currency, seller identity, price and delivery/tax wording. **No login, basket, checkout, account creation, address entry, notifications, contact, purchase, API token use or service changes.** If a required total exists only after these actions, record `not observed: requires excluded step`.
6. **Stop rules:** stop that host on 401/403/429, CAPTCHA, login wall, explicit automated-access restriction or ambiguous redirect. No retries, fallback browser engines, connector lanes or circumvention. A legitimate zero result is distinct from blocked, parser failure, cap reached and not attempted.
7. **Receipt schema:** UTC start/end; operator and approved protocol version; route/host/lane; query/category/filters/sort; destination stated or unknown; session logged-out state; page/cursor and caps; result count and inspected count; discovery origin; listing/seller/PID/SKU and exact displayed variant; complete watch/accessory; new/used and purchase mode; price/currency; stock wording; shipping/tax components separately with unknowns; response/error; final status `success/zero/partial/blocked/not-attempted`; minimal evidence pointer and allowed retention basis. Preserve no personal profiles, reviewer identities or full community threads. If retention is unresolved, keep only the operational failure/coverage receipt and source URL, not captured third-party content.
8. **Output:** one route receipt per attempt and a matrix update with field sufficiency, omissions and evidence level. Record repeated monitoring as **not tested**. A second separately approved session 24–48 hours later may revisit at most ten successful exact URLs under the same rules and caps; this tests re-identification/change capture, not usual price or longitudinal sufficiency. Credentialed APIs, connector normalisation and checkout remain separate untested layers.
