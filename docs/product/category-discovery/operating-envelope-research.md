# Operating envelope: reuse, unknown costs and a bounded measurement plan

Research dated 2026-10-27 for [the operating-envelope ticket](tickets/operating-envelope.md). Proposed planning decision for parent review; no tracker status or implementation changes. The research skill is applied as the assigned worker without recursive delegation.

## Finding and gate assessment

Reuse the existing application scheduler, connector execution, SQLite, health reporting, browser adapters and notification dispatch. There is no evidence here justifying a second scheduler, queue, browser service, credential store or AI service. There is also **no measured affordable breadth, freshness SLA, monthly cost or operator workload**. Existing access receipts establish small bounded operations, not sustainable recurring collection. The research gate can be met by explicitly accepting these unknowns and the learning plan below; a production operating envelope cannot yet be accepted.

The user must later choose spend/time limits. No numerical cap, collection cadence, retention period or maintenance commitment in this report is their approved budget. Source rights, offer qualification and measured capacity are separate gates: a cheap successful HTTP request cannot satisfy either of the first two.

## Request, storage and cost model

**P — accounting model, not an estimate.** For route `r`, define daily runs `n_r`, discovery pages per run `p_r`, selected-offer detail/rechecks `d_r`, and extra actual attempts `x_r` (fallbacks, retry, redirect/API acquisition). Then:

- Provider operations/day: `R_r = n_r × (p_r + d_r) + x_r + auth_r`. Account for detail batching/cache reuse only if actually observed and permitted. Count the same request once in its provider ledger, while tagging which tracking rules benefit.
- Browser work/day: `B_r = actual navigations`, `T_r = sum context-seconds`; collect origin subrequests and transferred bytes separately. Browser RPCs, pages, merchant requests and CPU seconds are different units. Product controls/evaluation may add RPCs without navigation.
- AI: no required AI acquisition stage is established in the inspected executor/browser path. Model future optional calls as `A`, input/output tokens and retries by task/model. `A=0` is a proposed deterministic/manual study arm, not a measured production count. No AI price or subscription entitlement is assumed.
- Retained observations: `O = sum_r(n_r × qualified observations/run × retained days_r)`, before deduplication. Acquisition outcomes must also be retained, including unchanged prices and failures; only changed-price events cannot measure coverage.
- Storage: `S = current snapshots + O × measured observation bytes + outcomes × measured outcome bytes + evidence bytes + indexes/WAL + logs + backups`. Apply separate retention horizons per class and source grant. Images/screenshots/HTML can dominate; response caps do not bound complete browser traffic or disk overhead. Measure allocated disk, not just JSON payload length. Deletion may not immediately shrink SQLite files.
- Money/month: `sum(actual billable units × current applicable quoted rate) + incremental hosting/storage/egress + allocated fixed costs if desired`. Operator effort: `sum(incident triage + access renewal + parser/fixture review + semantic review + retention/restore work)` in minutes. Avoid double counting bundled units or shared host allocation.

Populate each variable with sample count, capture window, source/version and observed min/median/max (tail percentiles only with sufficient samples). Forecast low/high scenarios from observed ranges plus explicitly stated growth/failure assumptions; they are scenarios, not confidence bounds or guarantees. Unknown terms stay unknown rather than zero. Reconcile request counters to provider usage and billing before quoting a cost. Obtain current first-party plan prices, quota units/reset rules, shared-account consumption, tax/currency and storage rights at that point; none was requested or purchased here.

## Bounded proposed measurement study

This is a design for later authorization, not permission to execute. Gate each route on its accepted acquisition and retention rights; if a grant is absent, measure fixtures/local artifacts only. Keep the five-case roster and blocked families visible from the source decision. Do not collect a price series merely to answer this ticket.

1. **Inventory first:** reconcile deployed version/config, existing scheduler count, process count, shared browser/search capacity, account plan/usage, permitted evidence retention, DB/backups and monitoring already present. Use existing access and observability; do not install a parallel stack. Record no secret values. Check startup/immediate-run behavior before any scheduler-based measurement.
2. **Offline accounting proof:** replay retained permitted/synthetic fixtures for successful, empty, capped, blocked, auth, timeout, 429, truncated-page, partial-source and cleanup-failure paths. Demonstrate pre-admission accounting, bounded retry/fallback, restart/overlap behavior, last-good evidence preservation, disk-cap/deletion and no duplicate notification. No service traffic or paid AI needed for this arm.
3. **Small prospective acquisition:** after separate approval, specify one route/query at a time, an explicit finite page/detail/attempt count, context concurrency, wall-clock stop, data-byte stop and permitted capture/expiry policy. Start with the already retained four-operation eBay shape or one AliExpress discovery plus one inspected product, only if that route's prerequisites pass. Those are candidate experimental shapes, not approved quotas. Do not automatically follow next pages, broaden the cohort or retry access denial. Log actual retries/auth/subrequests rather than counting only planned requests.
4. **Repeated freshness arm:** only after rights and user cadence/duration/cost/time choices, repeat the same eligible subjects at approved intervals with source outcomes. Compare price/stock/identity/component/coupon change intervals and detection lag, not just response success. Include a user-approved manual review sample to measure false qualification and minutes. A finite pilot cannot establish annual maintenance or seasonal sale behavior.
5. **Report and stop:** return counts, bytes, duration/resource ranges, failures/recovery, operator minutes, rights exclusions and attribution/billing reconciliation. Stop at the first cap or authority failure. Expansion needs a new explicit study scope; inconclusive results are valid.

Before execution the parent must record numerical ceilings and an owner for every applicable dimension: requests by provider, pages/details, browser contexts/seconds, AI calls/tokens/spend, storage/log bytes, study duration and operator minutes. This report deliberately supplies no invented user budget. If some provider operations cannot be observed or bounded, that lane cannot claim an enforced cap.

## Freshness, recovery and graceful capped degradation

**P.** Store acquisition time, source-provided update time (if any), latest attempt/outcome, latest successful qualified observation, query/page coverage and budget state separately. Specify source/claim-specific validity windows after the study; no universal TTL follows from the one-hour auth threshold or four-hour watch default.

Recheck selected SKU, stock, destination, cost components and coupon terms before a current ranking/alert when their evidence is expired or conflicting. A click-through may require a fresh review; preserve what was observed and when, without promising checkout equality. Identity/currency/merchant/condition corrections invalidate dependent comparisons, baseline and alerts immediately, independent of age. Apply the [history](observation-history-research.md), [UK-cost](uk-cost-research.md), [discount](public-discounts-research.md) and [baseline](baseline-policy-research.md) contracts rather than refreshing transport alone.

At a cap: defer lower-priority discovery first under a user-chosen priority policy; reserve recheck capacity explicitly rather than silently borrowing from tomorrow. Reduce breadth/frequency visibly, show checked/eligible/planned sources, inspected/discovered counts, last successful capture, overdue age, skipped reason and next eligible attempt. Do not claim best across unchecked sources. Mark old evidence stale; withhold current-price/stock/discount alerts and savings claims when their required evidence fails. Keep dated leads available only within their retention grant. Budget exhaustion is neither an empty market nor source failure.

Respect provider retry instructions within the approved attempt/time budget; no automatic switch to an unapproved paid lane, account, proxy or browser identity. Auth/permission denial stops that route for operator review. Timeouts/transient errors get bounded backoff; persistent failures open an explicit degraded state. Recovery resumes approved cadence without a catch-up storm; record gaps rather than interpolate history. The current executor's snapshot replacement and scheduler's immediate tasks require verification/correction before these proposed semantics can be claimed implemented.

## Privacy, access and maintenance boundaries

**S/R.** [auth.py lines 10–15](../../../src/pricerecon/api/auth.py#L10) and [app.py lines 114–130](../../../src/pricerecon/app.py#L114) make API-key protection conditional on configuration; source alone does not prove deployed access control. [token_store.py lines 19–47, 66–84](../../../src/pricerecon/core/token_store.py#L19) serializes OAuth token data into a SQLite-backed store; no encryption-at-rest guarantee follows from this code. Treat DB/config/backups as secret-bearing. Do not inspect/export token values to establish usage counts.

**R** [eBay logging correction](ebay-auth-logging-fix.md) fixes identified future diagnostic leakage; historical logs were not certified or rotated. **S** [browser server lines 16–53, 160–200](../../../services/cloakbrowser/server.mjs#L16) has redaction/trimmed evidence paths; this is not a guarantee that every HTML/API response is safe. Keep browser endpoints private with existing deployment controls verified before use; do not infer isolation or authorization from `/health`.

**P.** Default the measurement plan to anonymous public evidence. Do not link accounts, add addresses/postcodes, cart/checkout state or personal benefits without separate scope. Minimize seller/person identifiers and buyer preferences; retain public product evidence only as permitted. Never retain cookies, storageState, bearer headers, signed URLs or secret-bearing raw failures in research artifacts/AI prompts. Redact before persistence and review representative output; secret scanning alone is insufficient. Isolate connector/merchant sessions, close owned contexts and report failed cleanup rather than suppressing its resource/privacy consequence.

Choose per-source retention for normalized observations, raw evidence, images, logs, secrets and backups separately. Record provenance, rights basis, expiry, deletion request/correction lineage and backup expiry; deny acquisition if required evidence cannot legally be retained. Deleting raw evidence can invalidate reproducibility and downstream claims; retain a permitted minimal invalidation/outcome record and withdraw unsupported claims. No indefinite archive or numerical retention period is approved here.

Maintenance needs a named operator before activation, not an assumed always-available user: own entitlement/terms renewal, key expiry/rotation, scheduler liveness, usage/disk alarms, parser/semantic fixture drift, incident triage, backup/restore/deletion proof and stop/resume decisions. Review parser schema/field completeness, selected-option binding, currency/destination and coverage drift separately from HTTP health. Compare connector/build/policy versions in each receipt. Recheck access/terms at activation and on provider notice, access denial, route/schema changes or changed intended use; refresh prices/quotas immediately before budgeting and whenever the plan changes. The user must choose a sustainable review cadence and escalation time after measured operator workload. Unowned maintenance or an exceeded operator-time cap means pause and expose the gap, not silently self-expand.
